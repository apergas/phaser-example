# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Layout

- Single **Flutter** app at the repo root (Android, iOS, web), Dart package `farming`. All game logic and all views live in `lib/`.
- `lib/core/` — `assets/` (`images/lpc/`: the only copy of the art, with `CREDITS.md`, and also the arena atlas `arena.{png,json}`; `images/icons/`: HUD SVG icons, including `arena.svg`; `i18n/translations/es.json` + `i18n/internationalize.dart`), `config/` (`constants/enum/` with every enum, screen-only ones in `enum/forest/` and `enum/arena/`; `di/` with `locator.dart`, `di.dart`, generated `di.config.dart`, `di_environment.dart`; `env/` with `EnvironmentConstants` and the dev/prod `--dart-define-from-file` JSON files), `error-handling/` (`CustomException`, `AppException` cases, `AppExceptionHandler`), `services/logging/` (`Logger`, `CustomLoggerImpl`, `BlocLogger`), `services/navigation/` (`NavigationService` + `NavifyImpl`: navigation, snackbars, error pop-ups and the `routeObserver` that `ContainerApp` registers and pages listen to with `RouteAware`), `utils/` (`seeded_random.dart`, `kebab_case.dart`).
- `lib/layers/domain/`, `lib/layers/data/`, `lib/layers/presentation/` — see Architecture.
- `test/` mirrors `lib/`; `test/mocks/` holds centralised mock data; `test/helpers/` has `loadSpanishTranslations` (`spanish_translations.dart`), `pumpUntil` (`pump_until.dart`), `loadRobotoFont` (`roboto_font.dart`: the SDK's Roboto, so HUD widths are real) and `hud_test_app.dart`; `test/architecture_test.dart` enforces the layer rules.
- `android/`, `ios/`, `web/` — Flutter runners (app name `Farming`, ids `com.apergas.farming`, landscape only on mobile: Android `userLandscape`, iOS landscape left/right + full screen).
- `asset-packs/lpc/` — raw LPC art, `build_assets.py`, which generates `lib/core/assets/images/lpc/`, and `build_app_icon.py`, which draws the app icon (the oak of `forest.png` on `#0E150E`, also the launch colour) for Android (legacy icon plus the adaptive icon foreground), iOS and the web.
- `.github/workflows/deploy.yml` — Flutter pinned to 3.47.6 (`flutter-version` in `subosito/flutter-action`, bump it in its own commit); on pushes to `main` that touch the app: `build_runner` + `git diff --exit-code`, `flutter analyze`, `flutter test`, golden tests in Chrome, `flutter build web --base-href /phaser-example/` (production env file) and publish `build/web` to GitHub Pages (https://apergas.github.io/phaser-example/). Android and iOS are tested locally only.
- `docs/GAME_DESIGN.md` — game analysis and ideas for new mechanics (not implemented).

## Architecture

Team conventions from the `flutter-arch-conventions` plugin: `PRESENTATION -> DOMAIN <- DATA`, `CORE` used by all. `test/architecture_test.dart` checks that domain imports nothing from data/presentation nor Flutter/Flame/`dart:ui`/`dart:io`, data never imports presentation, presentation never imports data, core imports nothing from `layers/` (except the NavigationService widgets), nothing outside `domain/world/` imports its internals (`WorldState`, `Work`, the systems), Flame stays in `forest/game/`, `arena/game/` and the two pages, and entities have only `final` fields.

- `lib/layers/domain/`
  - `entities/<feature>/` — immutable `*Entity` classes: `final` fields, `const` constructor, `copyWith`, computed getters, hand-written `==`/`hashCode`. Geometry, tree (`TreeEntity`, `TreeStatsEntity`, `StumpEntity`: id, kind, position, `elapsedMs` since the felling), rock (`RockEntity`: id, position, radius, `stoneYield`, `hitsToBreak`, `hitsTaken`, with `footprint`, `hitsRemaining`, `isBroken`), item, decoration, building (`BlueprintEntity`, `BuildingEntity`), player (`InventoryEntity`, `PlayerEntity`, sealed `ActivityEntity`, sealed `IntentEntity`), game (sealed `GameEventEntity`, sealed `ConstructionResultEntity`, `PlayerStatusEntity`, `WorldSnapshotEntity`, `QuestProgressEntity`, `StatsEntity` (`treesFelled`, `treesFelledByKind`, `buildingsCompleted`, `treesRegrown`), `BuildOptionEntity`, `GameSessionEntity`), hero (`CombatStatsEntity` with an attack range, `attackMin`–`attackMax`, `HeroEntity` with `skillLevels` (`SkillId` → 1–3, no entry = not learned), `HeroStatusEntity` with `isChampion`, `SkillEntity` with one cost per level (`costs`, `maxLevel`, `costOf(level)`), `SkillOptionEntity` with the current `level` (0 = not learned), `nextLevel` and `nextCost` (`null` at the top), a `SkillOptionState` (`maxed` at the top), `missing` and `canLearn`), gear (`GearEntity`, `GearOptionEntity` with a `GearOptionState`, `missing` and `canBuy`), combat (`EnemyEntity`, `ArenaLevelEntity` (with an `enemySkillChance` in `0..1`, 0 by default), `FightTurnEntity`, `FightLogEntity`, `ArenaEntity`, `ArenaLevelStatusEntity`, sealed `FightResultEntity`: `FightPlayedEntity` with an optional `FightAdvice` and `isFirstChampionship`, `FightLockedEntity`).
  - `combat/` — `Combat`, pure functions: `resolve(…, seed)` plays a whole fight with `SeededRandom(seed)` (`StartFightUseCase` passes `hero.fightsFought`) and returns a `FightLogEntity` (the call order of `next()` is part of the contract: one per hit, plus one per enemy attack when the hero can dodge); each blow picks a value in the attacker's `attackMin`–`attackMax` with its `next()` and deals `max(1, value − defense)`, capped at the health left (the hero's *Golpe doble* second blow multiplies it by `1 + Rules.doubleStrikeBonusByLevel`, rounded). `resolve` takes the hero's `skillLevels`: a level only changes numbers (`Rules.doubleStrikeBonusByLevel`, `dodgeChanceByLevel`, `secondWindHealByLevel`), never the rolls, so level 1 gives the old logs; enemies use `Rules.enemySkillLevel` (1). Enemy skills (`EnemyKindRules.skills`) only roll when the level's `enemySkillChance` is > 0 and the kind has the skill (`random.next() < enemySkillChance`), so levels without a chance keep the exact old logs: before each hero blow the target rolls *Esquiva* (a hero turn with `dodge`, 0 damage, no damage roll), after it an enemy with *Segundo aliento* below the threshold rolls once per fight (an enemy turn on itself with `secondWind`); after each enemy attack (and the hero's second wind) it rolls *Golpe doble* if the hero is still standing (a second blow with `doubleStrike`). `adviceFor` reads a lost fight and leaves the hero's dodged blows out of the average damage.
  - `world/` — `World`, the mutable aggregate and only entry point that changes the game. It owns a `WorldState` and delegates to systems: `Navigation`, `Woodcutting`, `Mining`, `Construction`, `Depositing`, `pickUpItems`, `Regrowth`. The player's inventory is the carried load: `Rules.carryCapacity` (10) of what `ResourceRules.takesCargo` (wood and stone; never gold, mana nor tools), read with `InventoryRules.load` / `freeLoad` / `isLoadFull` / `cargo`; a felled tree or broken rock adds only what fits (the event carries that amount, the rest is lost) and with a full load chopping and mining answer `carryFull` (after `unknown…` and `no…`). The village stock is `WorldState.stock` (`World.stock`): `Depositing` (`DepositIntentEntity`, `PlayerActivity.depositing`, `World.orderDeposit` → `DepositResult` `unknownBuilding` → `notADropOff` → `emptyLoad`) stands the player in front of a finished drop-off building (`BuildingRules.acceptsDeposits`: the camp or a storehouse) and after `Rules.depositIntervalMs` moves the whole load into the stock (`DepositedEventEntity`). Rocks (`WorldState.rocks`, `World.rocks`, `WorldSnapshotEntity.rocks`) are obstacles like trunks and buildings (`obstacles()` = trunks, rocks, buildings), so they block walking, placing and the regrowth of a stump less than 34 away; `Mining` is a copy of `Woodcutting` (`MineIntentEntity`, `PlayerActivity.mining`, a blow every `Rules.mineIntervalMs`, the pickaxe needed: `World.orderMine` → `MineResult` `unknownRock` before `noPickaxe`): the eighth blow removes the rock, adds `Rules.rockStoneYield` stone to the inventory and emits `RockHitEventEntity` then `RockBrokenEventEntity`; rocks never come back. Felling a tree leaves a stump with the tree's id in `WorldState.stumps` (`World.stumps`, `WorldSnapshotEntity.stumps`); `Regrowth.advance`, the first step of `World.advance`, grows it into a sapling after `Rules.sproutAfterMs` (`TreeSproutedEventEntity`) and back into the same tree (same id, kind and spot, stats from `treeKindStats`, appended at the end of `trees`) after `Rules.regrowAfterMs` (`TreeRegrownEventEntity`), waiting at that age while the trunk would block the player or the spot is blocked; `Construction.place` removes the stumps whose future tree would hit the new building. Stumps never block walking nor placing. `StatsRecording.record`, the last step of `World.advance` (after `pickUpItems`), updates `WorldState.stats` (`World.stats`) with the tick's events in order, taking the felled tree's kind from its stump; `AdvanceGameUseCase` updates the quests afterwards, so a quest that reads `stats` completes in the tick of the event. `World` also owns the hero (`hero`, `updateHero`) and the funds (`funds` = the stock, `earn` adds to it, `spend` = `WorldState.pay`, the one payment rule that `Construction.place` also uses: buildings, gear and skills are paid from the stock, and arena gold and mana go straight into it, never into the load). Work mechanics are an `IntentEntity` subtype + a `Work` + one case in `workFor()` (exhaustive `switch`). `advance(deltaMs)` returns `GameEventEntity`s. `world/extensions/` holds the entity operations (`hit`, `hammer`, `add`, `spend`, `missing`, `addTool`, `hasTool`, `walkTo`, `distanceTo`, `StumpRules` (`isSapling`, `isReadyToRegrow`, `grown`), `RockRules.hit`, `StatsRules` (`treesFelledOf`, `fellingTree`, `completingBuilding`, `regrowingTree`), `BuildingRules.acceptsDeposits`, `BuildingListRules.hasComplete` (whether there is a finished building of a blueprint) and `completeCount`, `InventoryRules` (`adding`, `unloading` and the load getters), `ResourceRules.takesCargo`...; `HeroRules`: `stats`, `power` (+`Rules.powerPerSkill` per skill level), `equipped`, `nextGear`, `withGear`, `levelOf`, `skills` (the learned ones, in `SkillId.values` order), `withSkill(skill, level:)`; `EnemyKindRules.skills` (bandits *Esquiva*, barbarians, wolves and bears *Golpe doble*, the chief both *Golpe doble* and *Segundo aliento*); `ArenaRules`: `isUnlocked`, `hasCleared`, `isChampion` (the hero has beaten `ArenaLevels.championship`, the barbarian chief), `rewardFor`, `afterFight`).
  - `quests/` (`Quest` with its `QuestLine`, `Quests` (village line, 7 quests: wood (`gatherWood` reads the stock), house, then `fellTenTrees`, `fellAnOak`, `gatherFortyWood` (reads `World.funds`), `buildTwoHouses`, `seeATreeRegrow`; then the hero line; 15 in all), `QuestLog` with sticky completion and one current quest per line), `rules/` (`Rules` tuning, including `treeKindStats`: wood and hits per `TreeKind`; `Blueprints` catalogue (house, storehouse (20 wood, a drop-off), forge, armory, mage tower; the three hero buildings also cost 10 stone; and the camp, last, with no cost, `isBuildable: false` (never offered nor placeable) and `isDropOff`), `Gear` catalogue (gold only; `workshopFor`: weapons at the forge, armor at the armory), `Skills` catalogue (three levels each, gold and mana, ×1.5 and ×2.25 per level, cheapest first; `Skills.building`: learned at the mage tower), `ArenaLevels`: levels 6–10 pay gold and mana, 1–5 only gold; the list order is the play order (a new level can go anywhere in the list, its `ArenaLevelId` always at the end of the enum; `ArenaRules.isUnlocked` also opens any level already cleared, so a game keeps its levels when new ones are inserted), and the combat constants of `Rules`), `repositories/{level,session}` (interfaces).
  - `use-cases/game/` — one `@Injectable()` class per action with a synchronous `call()`: start game, move player, chop tree, mine rock (`MineRockUseCase`), can place / construct building, resume construction (`ResumeConstructionUseCase` → `World.orderResumeConstruction`: tapping an unfinished building sends the player back to hammer it, keeping its progress and without paying again; tapping the building already being hammered returns `ok` without touching the world, so the swing is not restarted), deposit (`DepositUseCase`), advance, player status (the inventory is the load), stock (`GetStockUseCase`), world snapshot, build options (buildable blueprints only, missing amounts against `World.funds`), quests; `hero/`: `GetHeroStatusUseCase`, `BuyGearUseCase` (checks a finished workshop, the next tier and the funds, in that order; pays with `World.spend` and equips with `World.updateHero`), `GetGearOptionsUseCase` (per slot, from the equipped tier up), `LearnSkillUseCase` (learns level 1 (`ok`) or upgrades to the next one (`upgraded`): checks a finished mage tower, the top level (`maxed`) and the funds, in that order; pays the next level's cost with `World.spend` and sets it with `World.updateHero` + `withSkill`), `GetSkillOptionsUseCase` (one option per skill, in `Skills.all` order, with the hero's level and the state of the next level); `arena/`: `GetArenaUseCase`, `StartFightUseCase` (resolves, pays with `World.earn` and records the fight with `World.updateHero` in one synchronous call; sets `FightPlayedEntity.isFirstChampionship` when the hero beats the chief for the first time). Each reads the session from `GameSessionRepository`.
- `lib/layers/data/` — `datasources/level` (`LevelLocalDatasourceImpl`: seeded procedural forest that also decides each tree's kind and the ground decoration; then 12 rocks with their own seed (2026), after the trees so the forest does not move, ≥ 60 from every trunk and outside every canopy box; the pickaxe, the only item on the ground, at (1012, 812); the camp, a finished building at (700, 592) (`LevelDBO.buildings`, `BuildingDBO` + `BuildingMapperDBO`: no id → `level-building-<n>`, an unknown blueprint is an `InvalidLevelException`, `hitsDone = hitsToBuild`); the decoration is generated as before and loses what would lie on a rock, the pickaxe or the camp (`RockDBO` + `RockMapperDBO`, which sets the numbers from `Rules`); all-nullable DBOs in `local/dbo/`), `datasources/session` (in-memory, `@LazySingleton`: one game per app), `repositories/level` (`LevelRepositoryImpl` + injected `*MapperDBO`s), `repositories/session`. Errors go through `AppExceptionHandler`.
- `lib/layers/presentation/`
  - `app/` — `ContainerApp` (`MaterialApp` with easy_localization and the navigator key of `NavigationService`) and `ContainerAppBloc`, which replaces the start screen with `ForestPage` through `NavigationService`.

  - `features/forest/models/` — view models (`PlayerRenderData`, sealed `PlayerPose`, `HudData` (`stock` of the village and `carry`, a `CarryItemData` "Carga 7/10" with `isFull`), `QuestItemData`, `BuildItemData`, `ResourceItemData`, `ToolItemData`, `PlacementData`, `HeroPanelData`, `GearRowData`, `GearItemData`, `SkillItemData`) and sealed `ForestEffect` (with `GearPurchasedEffect`, `SkillLearnedEffect`, `TreeSproutedEffect` / `TreeRegrownEffect`, which have no snackbar, and `RockHitEffect` / `RockBrokenEffect`) (played once per emitted state).
  - `features/forest/game/` — Flame (`package:flame` / `flame_bloc` may only be imported by `features/forest/game/`, `features/arena/game/`, `forest_page.dart` and `arena_page.dart`; rule in `architecture_test.dart`): `ForestGame` (`update` caps `dt` at 100 ms once and uses that value for `ForestTicked` and for every component, so animations never run ahead of the simulation) + `ForestWorld` + `ForestSceneComponent` + `ForestStateListener` (reconciles components with `ForestData.world` by id; Documented exceptions to the plugin (keep them; do not "fix" them):

- E1 — `domain/world/`, `domain/quests/`, `domain/rules/` (and `domain/combat/` from the arena plan) exist besides entities/repositories/use-cases: the simulation is a mutable aggregate.
- E2 — entity operations live in `domain/world/extensions/`; entities keep only computed getters.
- E3 — use cases have a synchronous `call()`: the game advances per frame with no I/O.
- E4 — entities use the enums in `core/config/constants/enum/` (`TreeKind`, `ToolKind`, ...).
- E5 — `GameSessionLocalDatasource` stores the `GameSessionEntity` in memory (no DBO).
- E6 — repositories read only the local datasource (no remote, no cache-first).
- E7 — core has only `assets`, `config` (`constants`, `di`, `env`), `error-handling`, `services/{logging,navigation}`, `utils` (no network/storage/connection yet).
- E8 — sealed hierarchies are declared in a single file.
- E9 — `features/forest/` and `features/arena/` add `models/` and `game/` (Flame) next to `bloc/`, `widgets/` and the page; Flame stays confined to `game/` and the pages.
- E10 — `BlocLogger` logs only `onError` (`ForestTicked` arrives 60 times per second).
- E11 — BLoC and page tests use the real use cases over `MockLevelRepository` / `MockGameSessionRepository` and mock only `NavigationService`: use cases are `final class` and mockito cannot mock them.

Key cross-cutting conventions:

- **Arena fights are deterministic:** same hero and seed, same log; golden tests in `test/layers/domain/combat/combat_test.dart`.
- **Arena balance:** `test/layers/domain/combat/balance_test.dart` plays every arena level with 100 seeds for the expected hero of `BalanceScenarioMock` (60–95 % of wins, the first level may always be won; under 50 % one step behind; with the enemy skill chances of levels 6–10 (1.5 / 2 / 2.5 / 3 / 3.5 %) also ≥ 60 % with seeds 0–999; with the expected hero's skills at level 3, at most 95 % with seeds 0–99 and 0–999; for each arena resource, gold and mana, the earlier first wins plus three repeats of the last pay the expected gear and skills). Any change to `Gear`, `Skills`, `ArenaLevels` or building costs must keep it green; the final table lives in `docs/GAME_DESIGN.md` 3.8.
- **Positions are feet / trunk bases**, in world units = native art pixels; the domain and Flame are both Y-down (no conversion). The same point drives collision, sprite anchoring and draw order (component `priority` = base `y`).
- **New resource, tool or building:** a `Resource`/`ToolKind`/`BlueprintId` is the enum value (appended at the end) + its cases in `Internationalize` and `es.json`, `CustomIcons` (+ SVG in `lib/core/assets/images/icons/`), `SpriteNames` (+ atlas frame via `build_assets.py`) and, for buildings, `RenderConstants.buildingFrontOffset`; `lpc_atlas_test.dart`, `internationalize_test.dart` and `custom_icons_test.dart` fail if any piece is missing. A resource that never lies on the ground (gold, mana) needs no `SpriteNames` frame; every new resource widens the `ResourceBar`, and the breakpoint test of `hud_overlay_test.dart` fails until `HudOverlay.buttonsBelowWidth` and `narrowWidth` are measured again. `LpcAssetsMock` builds a frame for every `BlueprintId`, and new buildings reuse `build_cottage()` in `build_assets.py` (recoloured roof via `ROOF_RAMP`, taller with `roof_stretch`).
- **The map is level data:** the player starts holding the axe (`LevelMapperDBO` gives `ToolKind.axe` in the inventory; no axe on the ground and no pick-up quest), tree positions, kinds and ground decoration come from the data layer, while each tree's wood and hits come from `Rules.treeKindStats` through `TreeMapperDBO` (`TreeDBO.wood` is still generated so the seeded sequence stays the same, but gameplay ignores it); the view never picks art or places decor itself (`SpriteNames` maps kind → atlas frame).
- **Rendering constants** (`features/forest/game/render/render_constants.dart`, art-specific so not in `core`): camera zoom 2; LPC 64 px character frames, rows `up, left, down, right`, walk columns 1–8 at 10 fps, idle 2 columns at 2 fps; work sheets 128 px with sequences chop `[0,0,5,5,4,4,3,1]` and hammer `[0,0,5,5,4,4,1]` (mining uses the hammer sheet and sequence, `WorkTool.pickaxe`), frame chosen from `swingProgress` so the impact frame matches the hit; buildings drawn `RenderConstants.buildingFrontOffset` below their footprint centre (house and storehouse: 24 px, camp: 12 px); sprites drawn with `FilterQuality.none`. Arena: `arena/game/render/arena_render_constants.dart` (400 ms lead-in, 800 ms per turn, impact at half the turn; people walk up to their target during the first 35 % of the turn (walk frames, `ArenaFrames.approachReach`), strike in place with the slash frames and walk back after 65 %, stopping `approachGap` (30 px) short; 480×270 stage framed with a cover zoom between 1 and 3; hero facing right, enemies facing left; people have idle, walk and slash frames and hold their weapon: the hero the axe or the LPC arming sword of its equipped weapon (bronze short sword, iron, steel) and wears its equipped armour (work clothes, leather armour and bracers, chain mail, plate with pauldrons and a nasal helmet), one precomposed set per combination `hero[-<weapon>][-<armour>]` (`FighterRenderData.weapon` and `armor`, `ArenaSpriteNames.heroWith(weapon, armor)`; armour layers in `asset-packs/lpc/sources/armour/`), the veteran bandit (`EnemyKind.banditVeteran`, blue shirt) an iron sword; barbarians wear their own LPC layers (leather armour, beard, helmet) and the barbarian chief has his own frames (viking helmet, black beard) drawn ×1.25; wolves and bears (`ArenaRenderConstants.leapSequence`, an exhaustive `switch` on `EnemyKind`) bite or swipe with their own `attack-*` frames while `ArenaFrames.groundSpot` / `lift` make them leap at their target (`FighterRenderData.targetIndex`) during the first 40 % of the turn, stopping 30 px short, and back after 60 %, and they lie on their own `down` frame instead of tipping over; the hero's target, the first enemy still standing, has a ring under its feet (`TargetRingComponent`, `FighterRenderData.isTargeted`), and fallen fighters are drawn at half alpha).
- **New enemy kind:** the `EnemyKind` value (appended at the end) + its cases in `EnemyKindRules.skills`, `ArenaSpriteNames.enemy`, `ArenaRenderConstants.fighterScale` and `leapSequence`, `Internationalize.arenaEnemy` and `es.json`, and its frames in `arena.png` (`build_assets.py`, credited in `CREDITS.md`); `arena_sprite_names_test.dart` and `internationalize_test.dart` fail if any piece is missing.
- `GameWidget(autofocus: false)` is deliberate: with autofocus Flame swallows every key and Esc never reaches the page's `CallbackShortcuts`.
- Tree taps/clicks are pixel-accurate (texture alpha), so shadows and gaps between leaves fall through to movement. On the web, right click or Esc cancels placement; touch screens get the placement bar and the touch texts (`ForestBloc` gets `isTouchInput` from `ForestPage`; `Internationalize` has a `…Touch` variant of every text that says how to interact).

## Constraints

- `analysis_options.yaml` is the plugin's plus four excludes Flutter re-adds on every `pub get`/`analyze` (`build/**`, `android/**`, `ios/**`, `web/**`); keep them.
- Generated files (`di.config.dart`, `*.mocks.dart`) are committed exactly as `build_runner` writes them, never run through `dart format`; CI fails if they are stale.
- Versions only in `pubspec.yaml` (caret constraints, `sdk: ^3.13.0`); bump a dependency in its own commit. Android `compileSdk`/`targetSdk` 36 is a team rule.
- Plugin rules: folders kebab-case, files snake_case with type suffix, classes with type suffix (`TreeEntity`, `ChopTreeUseCase`, `LevelLocalDatasourceImpl`, `LevelDBO`, `LevelMapperDBO`, `ForestBloc`, `ForestPage`); `locator`, never `GetIt.instance`; no `@Injectable()` on BLoCs; no `Equatable`; nullable `copyWith` fields with `ValueGetter`; no comments in `lib/`; `dart format --line-length 120`; regenerate DI after any change outside `presentation/`.
- **No tests until T1** (decided 2026-10-17, from TC9.4 on): phases are built without writing or fixing tests and are checked with `flutter analyze lib` and by running the app; what to cover goes in the *Para T1* list of `docs/boost/plans/2026-10-17-extras/T1-tests.md`, the last phase, which writes and fixes every test with the rules below.
- Tests: mirror `lib/`; names `testWhen<Action>Then<Result>`; `// given`, `// when`, `// then`; mocks with mockito `@GenerateMocks`, BLoCs with `blocTest`; mock data as `static` fields in `test/mocks/**/<name>_mock.dart` (e.g. `TreeEntityMock.mock`), never declared inline in a test (no inline entities, view models, effects, poses, exceptions/errors or DBOs: add the variant to the mock file). Exception: `PositionEntity(x:, y:)` coordinate literals may stay inline as call arguments or expected values. App texts in tests come from `Internationalize` (only `internationalize_test.dart` spells out the Spanish strings it checks); arbitrary widget labels go in `test/mocks/presentation/widgets/widget_text_mock.dart`. Widget and page tests call `loadSpanishTranslations` and wait with `pumpUntil` from `test/helpers/`; page tests call `rootBundle.clear()` in `setUp`.
- Code, identifiers and comments in English; player-facing text in Spanish only in `es.json`, read through `Internationalize` (the app name `Farming` is the only per-platform text: `AndroidManifest.xml`, `Info.plist`, `web/index.html`, `web/manifest.json`).
- LPC art is CC-BY-SA 3.0 / GPL 3.0 / OGA-BY 3.0; the arena beasts (wolf, bear) are CC-BY 4.0 / OGA-BY 3.0 (see `CREDITS.md`) and CC-BY 4.0 art is accepted: any new LPC asset must be credited in `lib/core/assets/images/lpc/CREDITS.md`.
- Git flow: `main` (published) / `develop` (default) / integration branches `feature/PROJECT-X-arena` and `feature/PROJECT-X-town` / work branches named after the roadmap phase, e.g. `feature/PROJECT-C6-barbarians`. Commit, branch and PR titles carry the phase code instead of `PROJECT-X`: `[PROJECT-C6]: Add the barbarian chief`, `[PROJECT-C4-C5]: ...` when one commit covers two phases; the description does not repeat the code. `[PROJECT-X]: ...` only for work with no phase behind it (merging `develop`, repo chores). A git hook enforces `[PROJECT-123]`, `[PROJECT-X]` or `[PROJECT-C4]` / `[PROJECT-F1]` / `[PROJECT-C4-C5]` titles, branches as `(feature|bugfix|hotfix)/PROJECT-<code>-description`, and rejects any AI attribution (no `Co-Authored-By` for an AI, no Claude/Anthropic mentions).
